Lecture 5 - JavaScript in the Browser, DOM, and Asynchronous JavaScript

Lecture 5 - JavaScript in the Browser, DOM, and Asynchronous JavaScript. Duration: 2 hours. This lecture continues from Lecture 4 (language fundamentals). We apply JavaScript in the browser: how scripts load and run, the Document Object Model (DOM), events, and synchronous vs asynchronous execution—including callbacks, XMLHttpRequest, and the modern fetch() API. Connected to unit C4 and Lab 8, Lab 9; previews client-side data handling in C5 (see Schedule). An announced quiz may take place during this session (see course platform).

Learning outcomes

By the end of this lecture you will be able to:

  • Explain how JavaScript runs in web browsers: embedded vs external scripts, execution phases, and the single-threaded model
  • Compare synchronous, defer, and async script loading and when each is appropriate
  • Describe the DOM as a tree of nodes; distinguish element, text, and attribute nodes
  • Select elements with getElementById, getElementsBy*, and querySelector / querySelectorAll
  • Read and update page content with properties such as innerHTML and element attributes
  • Create, insert, replace, and remove nodes with DOM methods (createElement, appendChild, insertBefore, replaceChild, removeChild)
  • Navigate the node tree with parentNode, childNodes, firstChild, lastChild, and sibling properties
  • Attach event handlers and reason about when handlers run relative to page load and user actions
  • Explain why blocking JavaScript hurts performance and how non-blocking patterns help
  • Use callbacks for asynchronous work; describe AJAX and load data with fetch()

Bridge from Lecture 4

JavaScript is a high-level, dynamic, untyped, interpreted language, well suited to object-oriented and functional styles. In Lecture 4 we covered the language itself: lexical structure, types and variables, expressions and operators, statements, objects, arrays, functions, classes, modules, and regular expressions. This lecture moves from language to environment—how scripts run inside the browser and interact with HTML through the DOM.

JavaScript in web browsers

The document object represents the HTML document. document.getElementById(id) returns the element with that unique id. Each element has properties and methods to read or change its content and attributes (including presentation via CSS).

Event handlers are properties on window, document, and element objects. They associate functions that run asynchronously when events occur—for example document load, user clicks, network activity, timers, or errors in script code.

window.onload = function () {
  console.log("Document loaded");
};

const btn = document.getElementById("demo-btn");
btn.onclick = function () {
  alert("Clicked!");
};

Client-side applications use JavaScript to access and manipulate page content, use browser services (networking, graphics, geolocation, history, background workers, and more), and improve UX—for example animations, sortable tables, and progressive disclosure of content.

Adding JavaScript to pages

Embedded script

The <script> element adds JavaScript inline. It can appear anywhere in the HTML file; common practice is in the <head> or at the very end of <body> so the DOM exists before scripts that manipulate it run.

<script>
// JavaScript code goes here
</script>

External script

The src attribute points to a .js file by URL:

<script src="app.js"></script>

Advantages: separates content from behaviour; one file can serve many pages (cached after first download); enables libraries and third-party scripts (e.g. maps APIs).

Downsides: each external file is an extra HTTP request (mitigated by HTTP/2 and bundling); embedding third-party code has security implications—only load scripts from sources you trust.

How scripts execute

Execution happens in two broad phases:

  1. The document loads and code from <script> elements (inline and external) runs.
  2. The browser invokes event handler functions in response to asynchronous events.

JavaScript in the browser uses a single-threaded model: scripts and handlers run one at a time without concurrent threads in the same page context.

  • Synchronous (default): the HTML parser runs the script before continuing to parse and render—blocking.
  • defer: download in parallel; execute after the document is parsed and ready to manipulate.
  • async: download and run as soon as possible without blocking parsing while downloading.
<script src="analytics.js" defer></script>
<script src="ads.js" async></script>

Use defer when the script needs the full DOM but order relative to other deferred scripts matters. Use async for independent scripts (e.g. ads) where execution order is not critical. Scripts that call document.write during load cannot safely use async/defer in the same way.

Document Object Model (DOM)

The DOM is a cross-platform, language-independent API. In web pages, JavaScript uses the DOM to access, traverse, and manipulate HTML (and XML) documents. It is standardized by W3C and maintained as a living standard by WHATWG.

The DOM treats a document as a tree: each node is an object representing part of the document (elements, text, attributes).

Node types

  • Element nodes — HTML tags; can have children and attributes.
  • Text nodes — text inside elements; no child elements.
  • Attribute nodes — name/value pairs on elements (often accessed via element properties in modern APIs).

DOM standards (brief)

  • Level 0 — early browser implementations before a common standard.
  • Level 1 (1998) — full document model for HTML/XML.
  • Level 2 (2000) — events, namespaces, stylesheets, richer traversal.
  • Level 3 (2004) — XPath, keyboard events.
  • Level 4 (2015+) — current DOM feature set; browsers implement the living standard.

Selecting elements

The browser window represents the tab; window.document (or just document) is the page.

MethodDescription
getElementById(id)Single element with that id
getElementsByName(name)Collection by name attribute
getElementsByTagName(tag)Collection by tag name
getElementsByClassName(class)Collection by class name
querySelector(selector)First match for a CSS selector
querySelectorAll(selector)All matches (NodeList)
 
const title = document.getElementById("main-title");
const items = document.querySelectorAll("ul.menu li");
const firstBtn = document.querySelector("button.primary");

innerHTML gets or sets the HTML content inside an element. Prefer safer APIs (textContent, createElement) when content comes from users to avoid XSS.

const box = document.getElementById("demo");
box.innerHTML = "<p>Updated content</p>";
box.textContent = "Plain text only";

Creating and changing elements

MethodDescription
document.createElement(tag)Create a new element
parent.appendChild(child)Append as last child
parent.insertBefore(elem, ref)Insert before a reference node
parent.replaceChild(new, old)Replace a child
parent.removeChild(child)Remove a child
 
const list = document.getElementById("todo-list");
const li = document.createElement("li");
li.textContent = "Learn DOM APIs";
list.appendChild(li);

// Change attributes
const img = document.querySelector("img#avatar");
img.src = "photo.jpg";
img.alt = "Profile photo";

Event handlers (property style)

document.getElementById("save").onclick = function () {
  // handle click
};

In modern code you will often use addEventListener (covered in Lab 8) for multiple listeners and clearer separation.

Tables and simple animations

The HTMLTableElement API supports dynamic rows and cells: insertRow, deleteRow, insertCell, createCaption, and related methods.

Animations are often built by changing element styles over time. setTimeout(fn, ms) runs fn once after ms milliseconds; setInterval(fn, ms) repeats; clearTimeout / clearInterval cancel timers. Position can be updated with inline styles such as element.style.left.

let pos = 0;
function moveBox() {
  const box = document.getElementById("box");
  pos += 5;
  box.style.left = pos + "px";
  if (pos < 200) setTimeout(moveBox, 50);
}
moveBox();

Nodes, traversal, and NodeList

Everything in the document is a node represented as an object (element, text, document type, etc.). Useful navigation properties:

  • parentNode
  • childNodes (indexed collection; includes text nodes)
  • firstChild, lastChild
  • nextSibling, previousSibling

A NodeList is an ordered collection (e.g. from getElementsByTagName or querySelectorAll). It is array-like but not always a true Array—use indexing or Array.from(nodeList) when you need array methods.

const parent = document.getElementById("container");
const newP = document.createElement("p");
newP.textContent = "Hello from a new node";
parent.appendChild(newP);
// insertBefore(newP, parent.firstChild) — insert at top

Synchronous JavaScript and performance

JavaScript is a common cause of slow pages: while a script runs, parsing and rendering can stall. Small delays matter—research cited in industry talks links hundreds of milliseconds of load time to measurable drops in engagement and search ranking.

Browsers render synchronously in document order: later resources wait for earlier blocking scripts. Goal: load and run work in a non-blocking way where possible.

document.write

document.write inserts markup while the parser is still reading the stream. It assumes inline, synchronous loading—so it breaks expectations if the script is loaded asynchronously. Legacy tags and ads still rely on it; modern code should prefer createElement, innerHTML (with care), or frameworks—and use defer/async only when document.write is not used.

Blocking example

With a blocking script that busy-waits for 5 seconds in the <head>, a following inline alert runs only after the wait finishes. With async on the external script, the alert can appear before the long script completes—illustrating non-blocking download vs ordered execution.

Asynchronous JavaScript

Asynchronous code lets the browser stay responsive while waiting on I/O or slow work. Without it, every network request would freeze the UI.

Callbacks

Functions are first-class objects in JavaScript—you can pass them as arguments and invoke them later. A callback is a function passed into another function to run when work completes.

function getData(callback) {
  const data = fetchFromSomewhere();
  callback(data);
  return data;
}

getData(function (data) {
  alert("We have " + data);
});

Compose small callbacks carefully; deeply nested callbacks become hard to read (“callback hell”)—see callbackhell.com. Later you will use Promises and async/await (unit C5).

Rule of thumb: if an API needs I/O or heavy work (> ~15 ms), design it asynchronously from the start.

AJAX and XMLHttpRequest

AJAX (Asynchronous JavaScript and XML) means making HTTP requests in the background and handling responses with JavaScript—no full page reload. Historically this used XMLHttpRequest; modern code prefers fetch().

function loadXMLAsync(filePath) {
  const req = new XMLHttpRequest();
  req.open("GET", filePath, true);
  req.send(null);
  req.onreadystatechange = function () {
    if (req.readyState === 4) {
      if (req.status === 200) {
        processXML(req.responseXML);
      } else {
        alert("Error loading XML");
      }
    }
  };
}
// readyState: 0 uninitialized, 1 loading, 2 loaded, 3 interactive, 4 complete

Example processing: read <image> nodes from XML and append <img> elements to document.body with createElement and appendChild.

SPAs: AJAX enables single-page applications that rewrite parts of the DOM instead of loading entire new documents—UX closer to native apps. JavaScript updates the DOM as the user interacts.

The Fetch API

fetch(url) returns a Promise that resolves with the HTTP response. It is the modern replacement for many XMLHttpRequest use cases.

fetch("data.json")
  .then((response) => {
    if (!response.ok) throw new Error("Network error");
    return response.json();
  })
  .then((data) => console.log(data))
  .catch((err) => console.error(err));

Optional second argument configures method, headers, and body for POST, PUT, DELETE, etc. Detailed practice continues in unit C5 and Lab 10.
